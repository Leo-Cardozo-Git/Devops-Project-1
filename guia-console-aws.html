Recriando a Infraestrutura Manualmente no Console

O mesmo resultado do projeto Terraform — VPC, Subnet, Security Group e EC2 rodando o container do slideshow — só que clicando direto no console da AWS. Útil pra entender cada peça antes (ou depois) de automatizar.

Console AWS VPC · Subnet · IGW · Route Table EC2 + Docker Sem Terraform
// ordem de criação no console — cada peça depende da anterior já existir
01

Pré-requisitos

Diferente do Terraform, aqui tudo é feito clicando direto no console — não precisa de CLI, profile ou credenciais locais.

  • Conta AWS ativa, logada em console.aws.amazon.com
  • Region selecionada no canto superior direito — use a mesma do seu projeto Terraform (ex: us-east-1) pra não misturar recursos em regiões diferentes
  • Sua imagem já publicada no Docker Hub (leocardozo/mentes-brilhantes:1.0) — reaproveitamos a mesma do projeto Terraform
  • Seu IP público atual, pra restringir o acesso SSH (busque em checkip.amazonaws.com)
Por que fazer isso manualmente Repetir o mesmo laboratório no console ajuda a enxergar o que o Terraform estava abstraindo em cada módulo — é uma boa seção pra comparar no README: "entendi cada recurso manualmente antes de automatizar com IaC".
02

Criar a VPC

Vamos criar só a VPC nesta etapa — sem o assistente "VPC and more" da AWS, pra manter o controle explícito sobre cada peça, igual fizemos com os módulos Terraform.

VPC → Your VPCs → Create VPC
CampoValor
Resource to createVPC only
Name taginfra-web-aws-vpc
IPv4 CIDR10.0.0.0/16
IPv6 CIDR blockNo IPv6 CIDR block
TenancyDefault

Clique em Create VPC. Anote o VPC ID gerado (ex: vpc-0abc123...) — você vai precisar dele nos próximos passos.

03

Criar e anexar o Internet Gateway

É o que dá acesso à internet pra VPC — equivalente ao aws_internet_gateway do módulo vpc.

VPC → Internet Gateways → Create internet gateway
CampoValor
Name taginfra-web-aws-igw

Depois de criado, ele fica com status Detached. Selecione-o, clique em Actions → Attach to VPC, e escolha a infra-web-aws-vpc que você acabou de criar.

04

Criar a Subnet pública

VPC → Subnets → Create subnet
CampoValor
VPC IDinfra-web-aws-vpc
Subnet nameinfra-web-aws-public-subnet
Availability Zoneex: us-east-1a
IPv4 CIDR block10.0.1.0/24

Habilite IP público automático

Isso equivale ao map_public_ip_on_launch = true do módulo Terraform — sem isso, a instância nasce sem IP público.

Selecione a subnet → Actions → Edit subnet settings → Enable auto-assign public IPv4 address
05

Criar a Route Table e associar

Sem essa rota, a subnet fica isolada mesmo com o Internet Gateway anexado à VPC — é o equivalente ao aws_route_table + aws_route_table_association.

VPC → Route Tables → Create route table
CampoValor
Nameinfra-web-aws-public-rt
VPCinfra-web-aws-vpc

Adicione a rota para a internet

Selecione a route table → aba Routes → Edit routes → Add route
CampoValor
Destination0.0.0.0/0
TargetInternet Gateway → infra-web-aws-igw

Associe à subnet pública

Aba Subnet associations → Edit subnet associations → marque infra-web-aws-public-subnet
06

Criar o Security Group

Mesmas regras do módulo security_group: SSH restrito ao seu IP, porta da aplicação aberta.

EC2 → Security Groups → Create security group
CampoValor
Security group nameinfra-web-aws-sg
DescriptionAcesso SSH e HTTP para a aplicacao em container
VPCinfra-web-aws-vpc

Inbound rules

TypePortSource
SSH22SEU_IP/32
Custom TCP30000.0.0.0/0
Boa prática Nunca use 0.0.0.0/0 na porta 22. Preencha o campo Source com My IP — o próprio console AWS detecta e preenche seu IP atual automaticamente nesse atalho.
07

Criar o Key Pair

EC2 → Key Pairs → Create key pair
CampoValor
Nameinfra-web-aws-key
Key pair typeRSA
Private key format.pem (OpenSSH) ou .ppk (PuTTY, se for usar no Windows)

O download do arquivo .pem começa automaticamente — a AWS não guarda uma cópia, então se perder precisa criar uma nova key pair.

Boa prática Se já tem a infra-web-aws-key criada via Terraform, pode reaproveitar o mesmo .pem em vez de criar outra — só selecione o key pair existente no passo de lançamento da EC2, sem precisar desse passo de novo.

User data (Advanced details → User data)

É o mesmo script que o módulo ec2 do Terraform injeta via templatefile — aqui você cola direto, sem variáveis:

user-data (cole na caixa de texto do console)
#!/bin/bash
set -euxo pipefail

yum update -y
yum install -y docker
systemctl enable docker
systemctl start docker

docker pull leocardozo/mentes-brilhantes:1.0
docker run -d --restart unless-stopped \
  -p 3000:3000 \
  --name app leocardozo/mentes-brilhantes:1.0

Revise o resumo à direita e clique em Launch instance.

09

Validar a instância

Na lista de Instances, aguarde até:

  • Instance state → Running
  • Status check → 2/2 checks passed (pode levar 1-2 minutos)

Clique na instância e copie o Public IPv4 address na aba Details — é o endereço que você vai usar pra acessar a aplicação.

Tempo de espera Depois do status check passar, ainda leva mais 30-60 segundos até o user_data terminar de instalar o Docker e subir o container — os dois processos rodam em paralelo mas não são a mesma coisa.
10

Testar a aplicação

Abra no navegador, trocando pelo IP que você copiou:

navegador ou terminal
http://SEU_IP_PUBLICO:3000

# ou via terminal
curl http://SEU_IP_PUBLICO:3000

Deve aparecer o slideshow com as frases dos cientistas alternando a cada 6 segundos — a mesma aplicação do projeto Terraform, agora provisionada 100% manualmente.

11

Se não responder — depure via SSH

terminal local
ssh -i infra-web-aws-key.pem ec2-user@SEU_IP_PUBLICO

Dentro da instância:

dentro da instância
# ver se o user_data rodou sem erro
sudo cat /var/log/cloud-init-output.log

# ver se o container está rodando
sudo docker ps

# testar localmente, isolando rede de aplicacao
curl http://localhost:3000

Se curl localhost:3000 funcionar mas o acesso externo não, o problema é o Security Group (confira se a porta 3000 realmente está liberada para 0.0.0.0/0). Se nem local funcionar, o container não subiu — confira o log do cloud-init pra ver em qual linha o script parou.

12

Limpeza — evite cobrança

Diferente do terraform destroy (que resolve a ordem de dependência sozinho), no console você precisa deletar na ordem certa, senão a AWS recusa com DependencyViolation.

  1. Terminate a instância EC2 (Instances → selecione → Instance state → Terminate) e espere o status virar Terminated
  2. Delete o Security Group infra-web-aws-sg
  3. Na Route Table, remova a associação com a subnet, depois delete a Route Table
  4. Delete a Subnet infra-web-aws-public-subnet
  5. Detach o Internet Gateway da VPC (Actions → Detach from VPC), depois delete o IGW
  6. Por último, delete a VPC infra-web-aws-vpc
Atenção A instância t3.micro entra na camada gratuita da AWS (com limites mensais de horas), mas se você já tiver outros recursos rodando ou passar do limite do free tier, ela gera custo enquanto estiver Running — não esqueça o Terminate se for só um teste.
